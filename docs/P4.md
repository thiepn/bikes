# P4 — Exploded View, X-Ray, Systems & Inspection Modes

## Objective

Turn Bike Atlas from a component picker into a multi-mode inspection instrument.

P4 adds four orthogonal viewing modes over the same semantic Road R1 state:

- **Normal** — material-first product view.
- **Systems** — mechanical systems receive stable semantic colors.
- **X-Ray** — structural/exterior elements become translucent so mechanisms remain visible.
- **Exploded** — components follow authored separation vectors controlled by a continuous assembly slider.

## Design rule

Inspection modes are **viewer state, not pages and not duplicated models**.

The same component ID:

```text
bike.road.r1.rear-derailleur
```

remains selected whether the user is in Normal, Systems, X-Ray, or Exploded mode.

## Systems mode

System colors live in `engine/inspection/config.ts`, keyed by the canonical `BikeSystemId` vocabulary.

The calibration model currently visualizes:

- frame/fork;
- cockpit;
- front/rear wheel;
- tires;
- drivetrain/transmission;
- braking;
- saddle/seatpost;
- pedals.

The palette is an analytical overlay only. Normal mode preserves physical material colors.

## X-Ray mode

X-Ray does not make the entire bike uniformly transparent.

Exterior/structural components are tagged as shells. Those fade to low opacity while mechanical parts remain more legible. Selection and isolation still take precedence, so a selected shell can be inspected without becoming unreadable.

The production GLB can extend the shell registry to covers, motor housings, hub shells, suspension lowers, chain guards, and other enclosures.

## Exploded mode

Exploded view uses authored vectors rather than radial scattering.

Examples:

- front/rear wheel assemblies move away longitudinally;
- rims/hubs/rotors also separate laterally;
- cockpit rises and moves forward;
- saddle/seatpost lift backward;
- drivetrain parts move laterally;
- rear derailleur moves outward/down/back.

The 0–100% control multiplies these authored vectors continuously.

This is deliberately compatible with future authored curves and assembly graphs: P4 establishes the scalar and semantic contract without pretending the calibration rig contains real disassembly paths.

## URL state

Inspection state is shareable:

```text
/?view=systems
/?view=xray&part=rear-derailleur
/?view=exploded&explode=72
/?view=exploded&explode=55&part=cassette
```

Normal mode omits the `view` parameter.

## Keyboard

- `N` — Normal
- `S` — Systems
- `X` — X-Ray
- `E` — Exploded
- `I` — toggle isolation
- `Esc` — reset selected part

Shortcuts do not fire while typing or manipulating a form control.

## Production migration

The production Road R1 GLB only needs to provide the same semantic IDs. System colors, X-Ray shell membership, explosion metadata, selection, URL state, and inspection controls remain outside the GLB.

## Deferred

P4 does not yet implement:

- real fastener-by-fastener assembly order;
- curved/rotational explosion paths;
- internal component meshes;
- shader-based clipping planes;
- true section cuts;
- system-level selection;
- occlusion-aware callout labels;
- repair procedures.

Those depend on the production asset and assembly graph.
