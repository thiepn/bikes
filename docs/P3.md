# P3 — Part Selection, Highlighting, Semantic Navigation & Camera Focus

## Objective

Make Bike Atlas behave like an interactive machine rather than a passive 3D viewer.

P3 deliberately targets stable Road R1 semantic IDs. The temporary procedural calibration bike exposes a representative subset of those IDs so interaction can be proven before the final P2-authored GLB is available.

## Implemented

### Semantic interaction
- Click a visible component to select it.
- Hover provides immediate visual highlighting.
- Double-click isolates a component.
- Isolation fades non-selected parts instead of deleting scene state.
- Escape resets to the full bike.
- Keyboard `I` toggles isolation for the selected component.
- Clicking empty canvas resets selection.

### Semantic navigation
- DOM component navigator driven directly from the Road R1 registry.
- No duplicated display names or hardcoded fake component database.
- Selection panel exposes stable semantic ID and canonical model-node target.
- Only calibration components are surfaced until the production GLB exists.

### Camera focus
- Every available component can define its own authored focus pose.
- Camera position, OrbitControls target, and perspective FOV interpolate smoothly.
- Reset returns to the hero camera.
- The camera system consumes component IDs, not source mesh names.

### URL state
Selections are addressable as:

```text
/?part=rear-derailleur
/?part=frame
/?part=cassette
```

Reloading a supported calibration part restores its selection.

### Production migration contract

When Road R1 GLB replaces `PrototypeBike`:

1. GLB nodes map to the same `bike.road.r1.*` IDs.
2. The selection/navigation state does not change.
3. Camera focus data stays valid unless art direction requires adjustment.
4. SemanticPart-style event binding moves from procedural groups to imported GLB semantic nodes.
5. All 35 Road R1 components can be enabled in the navigator.

P3 therefore does not need to be rebuilt after P2B.

## Interaction hierarchy

```text
hover
  ↓
preview highlight

click
  ↓
semantic selection
  ↓
camera focus
  ↓
component information

double click / I
  ↓
isolation

Esc / empty canvas
  ↓
full-bike reset
```

## Accessibility

The 3D mesh is not the only navigation path. The DOM component panel provides keyboard-operable buttons for every currently exposed component. Selection state is announced via an `aria-live` region.

## Deferred

- X-ray / material modes.
- Exploded view.
- System-level selection.
- Occlusion-aware 3D labels.
- Automatic camera framing from real mesh bounding boxes.
- Production GLB semantic traversal.
- Repair/lesson sequences.
