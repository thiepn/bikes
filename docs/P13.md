# P13 — Bike Finder, Use-Case Profiles & Explainable Recommendation Engine

## Objective

Turn Bike Atlas's growing engineering model into a practical answer to:

> What kind of bike fits what I actually want to do?

P13 adds a transparent recommendation system driven by authored bicycle capability profiles and explicit user needs.

It does **not** rank brands, scrape market listings, use hidden AI judgment or pretend the current two-bike catalog covers every use case.

## Finder traits

The recommendation engine currently models ten capabilities:

- paved efficiency;
- mixed-surface ability;
- technical-terrain capability;
- distance efficiency;
- climbing capability;
- comfort/control;
- cargo utility;
- all-weather use;
- maintenance simplicity;
- suspension capability.

Every Bike Atlas archetype receives a 0–1 capability profile for these traits plus an authored explanation for why it receives that capability.

## Questions

The Finder asks seven questions:

1. riding surface;
2. primary priority;
3. typical distance;
4. amount of climbing;
5. cargo requirement;
6. maintenance tolerance;
7. weather/conditions.

Each answer contributes one or more explicit trait demands and importance weights.

No answer directly says “Road” or “MTB.”

## Scoring model

For each required trait:

```text
shortfall = max(0, user demand − bike capability)
```

Only unmet needs create a penalty.

A bicycle is **not** punished simply for having extra capability that the rider did not request.

Weighted shortfalls are combined into a 0–100 fit score.

This keeps the engine interpretable:

- high road-speed demand penalizes an archetype with weak paved efficiency;
- high technical-terrain demand strongly penalizes a rigid road bike;
- high cargo demand penalizes both current archetypes.

## Result language

Results are deliberately described as:

- **Strong current match**
- **Good current match**
- **Closest current match**

The Finder does not present the score as a probability.

If a high-priority requirement is poorly served by the current catalog, the result displays:

**Current catalog gap**

This is especially important while Bike Atlas contains only Road R1 and MTB M1.

## Use-case presets

P13 includes reusable starting profiles:

- Fast road
- Mixed exploration
- Trail riding
- Technical trail
- Daily utility

Presets simply populate the same seven questions; they do not bypass the scoring system.

Current deterministic outcomes:

```text
Fast road          → Road R1
Mixed exploration  → MTB M1
Trail riding       → MTB M1
Technical trail    → MTB M1
Daily utility      → closest current match + catalog-gap warning
```

The Daily utility preset intentionally demonstrates that Bike Atlas can say “neither current archetype is ideal.”

## Explainability

A result contains:

### Why it fits

The highest-value matched user needs, with bike-specific explanations.

### Watch-outs

High-demand traits where the bike underperforms the requested need.

### Platform trade-offs

Always-visible authored compromises of the recommended archetype, even when the numeric fit score is very high.

### Alternative

The second-ranked current archetype and its fit score.

The user can jump directly to:

- Explore the recommendation;
- Compare the top two results using P12.

## Shareable Finder state

A complete answer set is encoded as one versioned query parameter:

```text
?finder=v1:paved:speed:long:rolling:none:normal:fair
```

Question order is stable within `v1`.

Invalid or incomplete encoded values are ignored rather than partially trusted.

Finder and Compare are mutually exclusive when restoring URL state.

Finder state is also removed when entering Story, Learn or Workshop.

## Current archetype profiles

### Road R1

Strongest current traits:

- paved efficiency;
- distance efficiency;
- climbing;
- maintenance simplicity relative to a full-suspension platform.

Major limitations:

- technical terrain;
- suspension capability;
- dedicated cargo utility.

### MTB M1

Strongest current traits:

- technical terrain;
- suspension capability;
- mixed surfaces;
- comfort/control;
- all-weather rough-surface use.

Major limitations:

- paved-speed efficiency;
- maintenance simplicity;
- dedicated cargo utility.

## Extensibility

The recommendation engine is data-driven.

A future bicycle archetype joins the Finder by adding a new capability profile with the same trait vocabulary.

The questionnaire and scoring algorithm do not need to know whether the future bike is:

- Dutch/city;
- gravel;
- trekking;
- cargo;
- touring;
- folding;
- e-bike;
- electric cargo.

As those bikes are added, current catalog-gap outcomes can naturally become strong matches.

## Validation

`npm run validate:domain` now also runs `validate-finder.mjs`.

P13 validation checks:

- unique question IDs;
- unique option IDs;
- valid trait names;
- demand values within 0–1;
- valid importance weights;
- exactly one profile per current archetype;
- complete 10-trait profiles;
- complete trait explanations;
- valid use-case presets;
- stable v1 URL encoding shape;
- Fast road continues to prefer Road R1;
- Trail and Technical trail continue to prefer MTB M1;
- Daily utility retains a current catalog-gap warning.
