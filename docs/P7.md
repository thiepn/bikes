# P7 — Learning Engine Expansion, Guided Interactions & Assessment Framework

## Objective

Generalize P6's single drivetrain lesson into a reusable bicycle-learning system.

P7 adds:

- a lesson catalog;
- prerequisite-aware lesson availability;
- local progress persistence;
- best-score tracking;
- resume position;
- reusable multiple-choice challenges;
- reusable 3D component-identification challenges;
- generic lesson runtime;
- four beginner lessons.

No account or backend is required yet.

## Course catalog

Current lessons:

1. **How a derailleur drivetrain works**
2. **Wheels, rims and hubs**
3. **How disc brakes slow a bicycle**
4. **Frame and steering fundamentals**

Disc braking requires the wheels/hubs lesson first because understanding the rotor-to-hub relationship makes the braking lesson more coherent. The other lessons can be started independently.

The catalog shows:

- lesson system;
- duration;
- difficulty;
- locked/unlocked status;
- in-progress/resume state;
- completion;
- best score;
- overall completion percentage.

## Progress model

Progress is stored in browser `localStorage` under:

```text
bike-atlas.learning.v1
```

Stored per lesson:

- status;
- last step;
- best score;
- completion attempts;
- completion timestamp.

This is deliberately local-only. An account/Supabase layer can later synchronize this schema without being required for the learning experience today.

## Challenge framework

P7 defines two reusable assessment types.

### Multiple choice

Used by the drivetrain lesson.

Scoring rewards first-attempt recall:

- first try: 100;
- second try: 75;
- later correct answer: 50;
- unresolved: 0.

### Select component

A learner must identify a real semantic component.

The user can either:

- click the part directly in the Three.js bicycle; or
- use equivalent accessible DOM choices.

Current examples:

- identify the rear hub;
- identify the front brake rotor;
- identify the headset.

The lesson cannot advance until the challenge is solved.

## New calibration semantics

P7 adds simplified semantic geometry for:

- front brake caliper;
- rear brake caliper;
- headset.

The calibration rig now exposes 26 Road R1 components, allowing all four lessons to target actual 3D objects before the production GLB exists.

## Generic runtime

The lesson panel is no longer drivetrain-specific.

Every lesson is driven by data:

```text
lesson
├─ metadata
├─ prerequisites
└─ steps
   ├─ focus component
   ├─ highlights
   ├─ inspection mode
   ├─ optional drivetrain demo
   ├─ optional ratio controls
   └─ optional challenge
```

The drivetrain visualizer remains available only when a lesson step requests it.

## Validation

CI validation now checks:

- lesson IDs;
- step IDs;
- prerequisite existence;
- lesson prerequisite cycles;
- component references;
- calibration-rig availability;
- multiple-choice answer integrity;
- select-component candidate integrity;
- assembly graph integrity.

## Deep links

All catalog lessons remain directly addressable:

```text
/?lesson=drivetrain-basics&step=3
/?lesson=wheels-hubs-basics&step=2
/?lesson=braking-basics&step=1
/?lesson=frame-steering-basics&step=3
```

Direct deep links are intentionally useful for sharing/debugging and bypass catalog locking; the normal catalog respects prerequisites.
