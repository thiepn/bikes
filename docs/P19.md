# P19 — Cross-Bike Knowledge Graph, Concept Pages & Global Search

## Objective

Unify Bike Atlas's previously separate content families into one navigable knowledge system.

Before P19, users could search the encyclopedia of the currently selected bicycle and could separately open Learn, Workshop, Compare, Finder and History.

P19 adds a cross-bike layer that answers broader questions such as:

- How do braking systems differ across bike types?
- Why do Road R1 and Gravel G1 use different tires?
- How does Urban U1 internal gearing relate to derailleur gearing?
- Which lessons and Workshop procedures teach a concept?
- Where did a modern component idea come from historically?

## Architecture

P19 does **not** create a second content database.

The global knowledge index is derived from the existing canonical sources:

```text
BIKE_CATALOG
    │
    ├─ component encyclopedia nodes
    ├─ LESSON_CATALOG
    ├─ WORKSHOP_CATALOG
    └─ HISTORY_EVENTS

            +
            
   ENGINEERING_CONCEPTS
            │
            ▼
 searchGlobalKnowledge()
```

Component prose, lessons, Workshop procedures and history remain owned by their existing modules.

The concept layer only adds reusable cross-domain relationships.

## Engineering concepts

P19 begins with nine cross-bike concept nodes.

### Braking systems

Connects:

- Road R1 front brake;
- MTB M1 front brake;
- Urban U1 front brake;
- Gravel G1 front brake;
- road braking lesson;
- weather / utility braking context;
- brake inspection;
- pre-ride checks;
- 1890s braking / mobility history;
- Repack braking-history context.

### Tire volume, pressure & contact

Connects all four tire families and teaches:

```text
tire width
+ air volume
+ casing
+ rim
+ load
+ surface
+ pressure
→ contact / support / compliance / traction
```

It links Gravel and MTB tire education, Workshop tire checks and the 1888 pneumatic-tire history milestone.

### Chain drive & power transmission

Links the power path across:

- Road derailleur;
- MTB 1×;
- Urban internal-gear hub;
- Gravel 1×.

### Gearing, range & shifting

Contrasts:

```text
Road multi-ring derailleur
MTB wide-range 1×
Urban internal hub
Gravel wide-range 1×
```

with relevant Learn, Workshop and history links.

### Steering, geometry & control

Links frame geometry, handlebars, headsets and rider-position concepts across the four archetypes.

### Suspension & compliance

Shows that:

- MTB M1 has dedicated spring/damper suspension;
- rigid bikes still obtain compliance from tires, structure, contact points and rider movement.

### Wheels, hubs & axles

Connects:

- wheel structure;
- rims;
- freehubs;
- internal-gear hubs;
- axles;
- historical wire wheels and pneumatic tires.

### Cargo, mounts & utility hardware

Connects Urban racks/stands and Gravel frame/fork mounts with cargo lessons, Workshop checks and transport history.

### Frame architecture & rider position

Connects all four chassis families:

```text
Road R1
MTB M1
Urban U1
Gravel G1
```

and their different geometry / rider-position priorities.

## Concept page structure

A concept page contains:

```text
Concept
├─ summary
├─ core principles
├─ Across Bike Atlas
│  ├─ bike A component
│  ├─ bike B component
│  └─ ...
├─ Learn
├─ Workshop
└─ History lineage
```

The modern-component cards open the exact bike and semantic component in the 3D viewer.

Learn and Workshop cards enter their existing guided modes.

History cards transition directly into the P18 History workspace.

## Reverse graph edges

P19 is bidirectional.

Previously:

```text
concept → component
```

would have been enough for a static topic page.

P19 also adds:

```text
component → concept
```

When a selected component belongs to one or more concepts, its component-detail panel now shows an **Engineering concepts** section.

For example:

```text
Gravel G1 front tire
├─ Tire volume, pressure & contact
├─ Suspension & compliance
└─ related parts / Learn / Workshop
```

A user can therefore navigate:

```text
3D component
    ↓
concept
    ↓
other bicycle implementation
    ↓
lesson / Workshop / History
    ↓
another 3D component
```

without returning to a menu hierarchy.

## Global Search

The old current-bike **Encyclopedia** launch has been replaced by a global **Search** launch.

Search is no longer conditional on the selected bike's encyclopedia capability.

This matters for future Bike Atlas expansion: even a newly introduced foundation bike can still participate in global search through its available metadata while the rest of the knowledge system remains accessible.

Blank Search opens:

- the nine concept nodes;
- the four current bike families.

Typing a query returns ranked results across the six entity types.

Example queries:

```text
brakes
pressure
creaking
carbon
cassette
internal gear
Repack
cargo
tubeless
suspension
head angle
```

Result filters:

```text
All
Concept
Component
Bike
Learn
Workshop
History
```

## Deterministic ranking

P19 uses local deterministic text scoring rather than an LLM or external search service.

The ranking rewards:

1. exact title matches;
2. title token matches;
3. alias matches;
4. general content matches;
5. concept / bike / lesson relevance bonuses;
6. 3D-ready component availability.

Every query is therefore:

- local;
- reproducible;
- inspectable;
- usable offline after the app is loaded.

No AI API is required.

## Concept deep links

Concept pages are shareable:

```text
/?concept=braking-systems
/?concept=tire-volume-pressure
/?concept=chain-drive-power
/?concept=gearing-range-shifting
/?concept=steering-geometry-control
/?concept=suspension-compliance
/?concept=wheels-hubs-axles
/?concept=cargo-mounting-utility
/?concept=frame-architecture-rider-position
```

A valid `concept=` URL:

- enters Explore;
- opens global Search;
- opens the requested concept page.

Changing bike, opening Story, entering Learn/Workshop or following a component target clears the concept state appropriately.

## Validation

P19 adds:

```text
scripts/validate-global-knowledge.mjs
```

It validates:

- concept-schema version;
- unique concept IDs;
- required high-value concept nodes;
- minimum concept depth;
- cross-bike rather than single-bike targets;
- target bike IDs;
- target component IDs;
- duplicate target edges;
- linked lessons;
- linked Workshop procedures;
- linked History milestones;
- coverage of every current bike family;
- all six global search entity types;
- derivation from canonical catalogs;
- concept deep-link routing;
- Global Search UI;
- History / 3D bridges;
- component → concept backlinks.

It is now part of:

```bash
npm run validate:domain
```
