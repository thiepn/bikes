# P10 — Multi-Bike Architecture & Second Archetype Foundation

## Objective

Stop treating Road R1 as the Bike Atlas domain and make it one bike in a reusable multi-bike platform.

P10 introduces a bike registry, shared semantic accessors, bike-aware viewer state, bike-aware URLs, a second assembly graph, and a second interactive prototype.

## Bike registry

Current catalog:

```text
Bike Atlas
├─ Road R1
│  ├─ archetype: performance road
│  ├─ model: prototype
│  ├─ encyclopedia: full
│  ├─ Learn: enabled
│  └─ Workshop: enabled
│
└─ MTB M1
   ├─ archetype: full-suspension trail MTB
   ├─ model: prototype
   ├─ encyclopedia: foundation
   ├─ Learn: not yet authored
   └─ Workshop: not yet authored
```

Capabilities are explicit per bike. The UI therefore does not pretend Road lessons or Road repair procedures apply to MTB M1.

## Shared bike definition

Road R1 and MTB M1 now use the same normalized `BikeDefinition` schema.

The registry provides:

- lookup by bike ID;
- lookup by bike slug;
- global semantic component lookup;
- component-to-bike lookup.

This removes the need for future features to import a particular bike merely to resolve a component.

## MTB M1

MTB M1 is a generic full-suspension trail archetype.

It intentionally introduces architecture Road R1 does not have:

- suspension fork;
- rear shock;
- suspension linkage/pivots;
- flat handlebar;
- dropper seatpost;
- dropper remote;
- 1× drivetrain;
- single front chainring;
- wide-range cassette;
- large-volume trail tires;
- hydraulic disc brakes.

It does not contain a front derailleur.

## Second interactive prototype

MTB M1 is not only metadata.

P10 adds a lightweight procedural 3D prototype with semantic selection for:

- frame;
- fork;
- rear shock/linkage;
- wheels/tires/rims/hubs;
- rotors/calipers;
- headset/stem/flat bar;
- dropper post and saddle;
- crankset/chainring/chain;
- cassette/rear derailleur;
- pedals;
- thru axles.

The prototype uses the same:

- raycasting;
- selection;
- camera focus;
- Systems view;
- X-Ray view;
- exploded view;
- isolation;
- encyclopedia selection

as Road R1.

## Shared inspection logic

P10 removes Road-specific IDs from the shared inspection engine.

System colors resolve via the global bike/component registry.

X-Ray shell classification and explosion vectors are now keyed by semantic component slug, so common component concepts can reuse behavior across archetypes.

MTB-specific concepts such as rear shock and suspension linkage have their own authored explosion behavior.

## Shared camera logic

Camera focus now resolves components through the global registry rather than Road R1.

Shared slugs reuse focus presets while MTB-specific parts add:

- rear shock;
- suspension linkage;
- dropper post.

## Assembly graph

MTB M1 ships with an independent assembly graph covering the structural foundation:

```text
frame
├─ headset → fork
├─ rear shock ↔ suspension linkage
├─ bottom bracket → crankset → chainring → chain
├─ dropper post → saddle
├─ rear brake
└─ rear wheel

chain
├─ cassette → rear hub
└─ rear derailleur
```

The graph is intentionally a structural foundation; MTB Workshop operations are not invented before MTB-specific procedures are authored.

## Bike-aware URLs

Road R1 stays the default clean URL.

MTB M1 uses:

```text
/?bike=mtb-m1
/?bike=mtb-m1&part=rear-shock
/?bike=mtb-m1&part=dropper-post
/?bike=mtb-m1&view=systems
/?bike=mtb-m1&view=exploded&explode=65
```

Entering a Road-only lesson or Workshop procedure forces Road R1 and removes incompatible bike state.

## Encyclopedia boundary

Road R1 retains its complete P9 encyclopedia.

MTB M1 has a foundation encyclopedia:

- semantic names;
- systems;
- tags;
- material identifiers;
- assembly-neighbor relationships;
- search;
- 3D availability.

The UI clearly labels detailed MTB standards/symptoms/content as pending instead of inventing technical claims.

## Validation

P10 adds MTB-specific validation for:

- stable bike ID and slug;
- unique component IDs;
- unique model nodes;
- system membership;
- no Road-prefixed IDs;
- presence of MTB-distinguishing components;
- intentional 1× drivetrain;
- assembly references;
- interactive-prototype references.
