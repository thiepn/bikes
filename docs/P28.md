# P28 — Shareable Build Reports, Portfolio Export & Decision Explanations

## Objective

P28 turns P27 portfolio decisions into portable evidence.

A user can explain why a saved build is attractive, see its trade-offs against the current portfolio leader, copy or share a report, download a durable Markdown report, or export the evaluated portfolio as JSON.

P28 remains a reporting layer over the existing P27 decision model.

It does not introduce another compatibility engine, score model, geometry solver, gearing solver, Physics model, active-build state, or portfolio store.

## Decision explanations

The selected Portfolio candidate now receives a concise explanation generated from the current P27 evaluation state.

The explanation includes:

- portfolio rank and candidate count;
- aggregate selected-scenario score;
- strongest active scenario;
- weakest active scenario;
- scenarios where the selected build beats the current portfolio leader;
- scenarios where it trails the leader;
- meaningful mass difference versus the leader;
- meaningful lowest-gear difference versus the leader;
- current system-health state.

The explanation is comparative evidence, not a hidden AI judgement.

## Portable selected-build report

P28 adds a versioned report schema:

- schemaVersion: 1
- kind: bike-atlas-build-report

A build report contains:

- generation timestamp;
- bike id;
- saved name and source;
- current system health;
- portfolio rank;
- aggregate score;
- active scenario ids;
- per-scenario score, speed, cadence reference and closest gear;
- mass, CdA, gear span and saddle-to-grip drop;
- modified-slot count;
- sanitized canonical component selections;
- canonical encoded build selections;
- generated decision explanation.

The report is created from the already evaluated P27 candidate. P28 does not persist stale report scores back into the portfolio.

## Shareable build URL

P28 produces a reproducible Bike Atlas build URL by:

1. starting from the current Bike Atlas URL;
2. removing optimizer-only query state;
3. enabling Build Lab with build=1;
4. encoding the selected candidate into buildParts.

This lets a recipient inspect the actual component configuration without receiving the sender's browser-local P27 portfolio.

## Share and copy

The report workspace supports:

- Share report — uses the Web Share API where available;
- Copy report — copies Markdown plus the reproducible Bike Atlas build URL;
- graceful share fallback — copies the report when native sharing is unavailable.

Cancelling the native share sheet does not produce a false success notice.

## Markdown export

Download .md creates a human-readable durable report.

The Markdown contains:

- decision explanation;
- strengths;
- trade-offs;
- scenario table;
- build metrics;
- component selections;
- model-boundary disclaimer.

## Full portfolio JSON export

Export portfolio .json creates a portable bundle:

- schemaVersion: 1
- kind: bike-atlas-portfolio-export
- one generation timestamp;
- active scenario ids;
- one current report for every evaluated candidate.

The export is explicit and user-triggered.

P28 does not read raw localStorage into the export. It exports the current sanitized/evaluated Portfolio state supplied by P27.

## Privacy and storage boundary

P27 remains browser-local.

P28 sharing does not upload the user's full local portfolio anywhere.

A selected build can be shared as report text plus a reproducible Build Lab URL. Full portfolio data leaves the browser only when the user explicitly downloads the JSON export.

## Validation

P28 adds:

- domain/optimizer/build-report.ts
- components/optimizer/BuildReportActions.tsx
- scripts/validate-reports.mjs

The validator protects:

- schema version and report kinds;
- reuse of canonical build encoding;
- decision explanation generation;
- selected-build report creation;
- portfolio bundle creation;
- reproducible build URL generation;
- native share and clipboard paths;
- Markdown download;
- JSON export;
- Portfolio UI integration;
- visual selectors;
- validate:domain registration.

P27 validation remains active.

## Model boundary

P28 reports inherit every P27 model boundary.

They are educational decision records, not:

- purchasing advice;
- real-world trip predictions;
- rider-specific physiological forecasts;
- professional fitting;
- structural certification;
- manufacturer compatibility approval;
- reliability forecasts;
- price or inventory data.

A report explains Bike Atlas model outputs; it does not upgrade those outputs into real-world guarantees.
