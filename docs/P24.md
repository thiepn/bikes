# P24 — Full Build Geometry & Fit Consequence Solver + Dynamic Gearing Visualization

## Objective

P24 turns Bike Atlas build consequences into solved bicycle geometry and inspectable gearing.

The phase adds two connected views:

- Geometry + fit
- Dynamic gearing

Both use the same active custom build shared by Build Lab, the 3D scene, and Physics.

## Reference geometry

Bike Atlas now has one fictional reference geometry profile for each archetype:

- Road R1
- Gravel G1
- MTB M1
- Urban U1

Each profile defines head angle, seat-tube angle, reach, stack, wheelbase, chainstay, bottom-bracket drop, fork axle-to-crown, fork offset, front/rear wheel radius, and a reference saddle contact point.

These are Bike Atlas reference dimensions, not manufacturer frame charts.

Reference wheel radii are tied to the existing Physics Lab wheel circumferences so Geometry and Physics do not use contradictory wheel sizes.

## Component geometry metadata

P24 extends the compatibility catalog with geometry and gearing properties.

Forks now carry axle-to-crown, fork offset, and suspension travel.

Stems now carry length and rise.

Handlebars now carry reach, drop, and width.

Seatposts now carry setback.

Cranksets now carry authored chainring tooth arrays.

Rear transmissions now carry authored sprocket tooth arrays. The Urban internal-gear reference also carries eight internal gear ratios.

The compatibility interface value type now supports numeric arrays for this authored gearing data.

## Geometry solver

P24 adds:

- domain/geometry/solve.ts
- engine/geometry/types.ts
- content/geometry/profiles.json
- domain/geometry/catalog.ts

The frame reference remains fixed. Component selections only alter geometry that their authored data can affect.

### Tire radius

A selected tire family inherits the donor archetype reference circumference delta.

Front and rear radii are evaluated independently, so unequal tire changes can alter bicycle pitch.

### Fork height

The selected fork contributes its axle-to-crown difference.

The front-end height delta combines:

- fork-length change projected vertically by reference head angle
- front tire radius delta
- rear tire radius delta

The frame pitch is then derived with atan2 against reference wheelbase.

A taller front end therefore slackens the solved head and seat angles, increases solved stack, and reduces solved reach. A shorter front end does the opposite.

P24 is a static kinematic reference solver, not a suspension or structural simulation.

### Bottom-bracket height

The rear axle to BB vector is reconstructed from chainstay and BB drop, rotated by solved frame pitch, and placed above the effective rear tire radius.

This produces a build-derived BB height rather than simply adding fork length to the stock number.

### Trail

Mechanical trail is recomputed from effective front wheel radius, solved head angle, and selected fork offset.

The result is a steering-geometry reference, not a complete handling score.

### Effective reach and stack

Reference reach and stack are rotated by solved frame pitch.

This means fork or asymmetric tire changes can alter effective horizontal and vertical frame contact geometry even though the physical frame has not changed.

## Contact-point / fit consequences

The active grip point is solved from:

- effective frame reach and stack
- selected stem length and rise
- selected handlebar reach

The Geometry Lab exposes:

- grip reach from BB
- grip stack from BB
- saddle-to-grip horizontal reach
- saddle-to-grip drop
- bar width
- lower-drop grip height
- seatpost setback change

Seatpost setback is applied relative to the host reference post.

Saddle height remains at the reference contact height so component changes can be compared without inventing a personal fit adjustment.

## Fit boundary

P24 does not claim that a bicycle fits a rider of a given height.

The UI explicitly labels this output as contact-point consequences and not a rider-size recommendation.

A real fitting workflow would require rider-specific measurements, mobility, riding goals, saddle setup, and iterative validation.

## Reference-vs-custom diagram

The Geometry Lab renders a live side-profile SVG overlay of the reference bicycle and the active custom build.

The diagram includes both wheels, frame reference lines, fork, cockpit, saddle, BB, and the saddle-to-grip fit line.

It automatically rescales to include both states.

## Live geometry metrics

The metric grid reports current value and delta for:

- head angle
- seat angle
- frame reach
- frame stack
- wheelbase
- BB height
- trail
- fork axle-to-crown

The interpretation layer reports direction such as steeper/slacker, more/less trail, longer/shorter wheelbase, and higher/lower BB without converting those into unsupported quality claims.

## Geometry regression example

A Road R1 fork is statically compatible with the Gravel G1 host under the authored P23 interface and geometry-envelope rules.

The P24 solver produces approximately:

- head angle: +1.31 degrees
- stack: -9 mm
- reach: +13 mm
- BB height: -10 mm
- trail: -1 mm

This demonstrates why a part fitting does not mean bicycle geometry stays unchanged.

## Cockpit regression examples

Road R1 plus Gravel handlebar:

- frame geometry unchanged
- grip reach +5 mm
- bar width becomes 640 mm

Road R1 plus Gravel stem:

- grip moves about 20 mm rearward
- grip moves about 19 mm upward

These are contact-point changes without changing the physical frame reference.

# Dynamic gearing

P24 adds:

- domain/geometry/gearing.ts
- engine/geometry/gearing-types.ts

The gearing view uses the active crankset, rear transmission, wheel circumference, and cadence.

## External drivetrain

For every chainring and sprocket combination, the solver calculates:

- overall ratio = chainring teeth / sprocket teeth
- development = wheel circumference × overall ratio
- speed from development × cadence
- gear inches from effective wheel diameter

## Internal gear

Urban U1 uses the primary chain ratio multiplied by each authored internal gear ratio.

The reference exposes exactly eight internal gears and derives approximately 306% total range.

## Gear-map behavior

The Dynamic Gearing tab includes:

- cadence slider from 40 to 130 rpm
- architecture label
- total gear range
- easiest and hardest ratios
- one selectable row per gear combination
- overall ratio
- development in metres per revolution
- gear inches
- speed at selected cadence

Road R1 exposes 24 combinations from its 2×12 reference drivetrain.

At 90 rpm its easiest ratio is 1.00× and its hardest ratio is 50/11, approximately 4.545×.

Gravel with the compatible Road 2× crankset expands from the stock 1×12 gearing structure to 24 combinations. P23 may still mark that build mechanically blocked if required front-shifting hardware is absent.

Kinematic gearing and system coherence remain separate concepts.

## Kinematic vs Physics speed

Gear speeds are explicitly labeled kinematic.

A ratio can produce a theoretical wheel speed at 90 rpm even when the rider cannot sustain the required power.

Physics Lab remains responsible for power, drag, rolling resistance, gravity, and steady-state achievable speed.

## Build-aware wheel circumference

The gearing solver uses the P23 build-adjusted Physics profile.

Selected tire families can therefore alter wheel circumference, development, gear inches, and speed at cadence.

## Shared custom-bike state

Geometry receives the same effectiveBuildSelections used by Build Lab, the 3D scene, and Physics Lab.

No Geometry-specific build copy exists.

## URL state

Geometry uses:

- geometry=1
- geometryTab=gearing
- gearCad=100

The custom bicycle remains encoded separately through buildParts.

Closing Geometry removes its UI state while preserving the custom bicycle. Lesson, Workshop, bike changes, and return-to-story clean Geometry state as part of their normal mode reset.

## URL default hardening

During P24 a subtle JavaScript parsing issue was found: Number(null) evaluates to zero.

A missing gearCad parameter could therefore have been interpreted as zero and clamped to 40 rpm instead of using the intended 90 rpm default.

P24 now checks for null before numeric parsing.

The same pre-existing issue was corrected in Physics Lab generic URL-number parsing so absent parameters preserve their intended defaults.

## Validation

P24 adds scripts/validate-geometry.mjs.

It validates:

- four unique geometry profiles
- wheel radius and Physics circumference agreement
- geometry bounds
- stem geometry metadata
- handlebar geometry metadata
- seatpost setback metadata
- fork offset metadata
- crank chainring arrays
- rear sprocket arrays
- external gear-count consistency
- internal gear-count consistency
- internal range consistency
- Gravel plus Road fork geometry regression
- Road plus Gravel handlebar contact-point regression
- Road plus Gravel stem contact-point regression
- Road 2×12 ratio/count regression
- cadence linearity
- Gravel plus Road 2× gearing expansion
- Urban eight-speed internal range
- Geometry Lab rendering and fit wording
- Geometry deep-link routing
- Escape behavior
- shared active-build state
- Geometry 90 rpm default
- Physics absent-query default preservation

The validator is part of npm run validate:domain.

## Model boundary

P24 still does not model suspension sag, dynamic fork compression, tire deformation under load, exact frame collision, spacer stack, hood geometry, saddle tilt, detailed rail adjustment, rider biomechanics, steering flop, dynamic handling, or manufacturer fit recommendations.

The purpose is a deterministic and inspectable geometry consequence engine for the fictional Bike Atlas reference system.
