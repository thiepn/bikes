# P27 — Saved Build Portfolio, Scenario Presets & Multi-Build Decision Workspace

## Objective

P27 stops Bike Atlas from forcing every optimization decision through one active bicycle.

Users can now keep a small portfolio of candidate builds, compare them across several riding scenarios, and restore the configuration they actually want after comparing trade-offs.

The portfolio remains a decision layer over the existing canonical build model.

Saved entries do not create a second compatibility, Physics, geometry or gearing system.

Every saved build is re-sanitized and re-evaluated through the current P23–P26 engines whenever the Portfolio workspace evaluates it.

## Optimize now has three views

- Ranked — P25 single-goal optimization
- Frontier — P26 explored Pareto trade-offs
- Portfolio — P27 saved multi-scenario decisions

Portfolio is a first-class third Optimize workspace.

## Browser-local persistence

P27 stores saved candidates under:

`bike-atlas:p27-portfolio:v1`

Persistence uses browser localStorage.

Current limit:

`8 saved builds per host bicycle`

The limit is enforced both when saving and when reading/persisting older local data.

P27 is intentionally local-first.

It does not yet sync saved builds through an account or across devices.

## Host-scoped portfolio

Portfolio comparison is scoped to the active host bicycle.

A Road R1 portfolio does not silently switch the active bike to Gravel, MTB or Urban.

Saved entries still retain their bikeId so persisted data remains explicit and future migrations can safely reason about ownership.

## Sources

A saved build records one of three origins:

- current
- ranked
- frontier

The source is descriptive only.

Once saved, the configuration is evaluated from its component selections, not from an old optimization score.

## Canonical snapshot

A saved build contains:

- id
- bikeId
- editable name
- canonical component selections
- source
- saved timestamp

Before a new entry is stored, selections are sanitized through the active host compatibility model.

Blocked builds cannot be newly added to the portfolio.

Duplicate configurations are detected using canonical encoded build selections.

If the same bicycle configuration is already saved, P27 reports the existing saved name instead of creating a duplicate.

## Historical safety

A previously saved build can become invalid after later Bike Atlas rules change.

P27 therefore re-sanitizes and re-runs system analysis every time a saved build is evaluated.

If an old snapshot is now blocked:

- it remains visible for historical comparison;
- its aggregate score is forced to zero through the health factor;
- restore actions are disabled;
- the UI explains that it is no longer coherent under current rules.

This preserves history without letting stale data bypass newer mechanical constraints.

The saved portfolio itself remains browser-local and is not encoded into the URL.

# Scenario evaluation

P27 adds:

- content/optimizer/scenarios.json
- engine/optimizer/portfolio-types.ts
- domain/optimizer/scenario-catalog.ts
- domain/optimizer/evaluate-portfolio.ts
- domain/optimizer/portfolio-storage.ts
- components/optimizer/BuildPortfolioPanel.tsx

For each saved build and active scenario, Bike Atlas uses:

- current build compatibility sanitization;
- P23 system-health analysis;
- build-aware Physics profile;
- steady-state Physics simulation;
- P24 gearing solution;
- P24 geometry solution.

## Performance component

The scenario steady-state speed is normalized against the preset speed range.

The normalized result is bounded from 0 to 1.

## Cadence / gearing component

The gearing solver is run at the scenario reference cadence.

P27 finds the available gear whose kinematic speed is closest to the Physics steady-state speed.

The relative mismatch becomes a cadence-fit score.

An exact match scores 1.

A mismatch of 25% or more scores 0.

## Scenario score

Current formula:

`score = 80% performance + 20% cadence fit`

The result is displayed on a 0–100 reference index.

System health then applies:

- ready: 1.00
- attention: 0.97
- blocked: 0.00

## Aggregate score

The multi-scenario score is the arithmetic mean of all selected scenario scores after the system-health factor.

This makes the ranking react immediately when scenarios are added or removed.

The aggregate is a decision index, not a universal bicycle rating.

# Decision workspace

The Portfolio table ranks all saved builds for the current host.

Columns include:

- build name
- aggregate score
- one column per active scenario
- raw scenario speed
- bike mass
- lowest gear

Selecting a row opens the detailed inspector.

## Selected-build inspector

The inspector shows:

- editable saved name
- original source
- modified-slot count
- current P23 health
- aggregate scenario score
- scenario speed
- scenario score
- closest gear at the scenario cadence
- closest-gear kinematic speed
- bike mass
- CdA
- low-to-high gear span
- saddle-to-grip drop

Scenario score bars make multi-scenario differences inspectable without hiding the raw values.

# Saving candidates

## Save current build

Portfolio can snapshot the currently active custom bicycle.

The stock/reference bicycle can also be saved as a baseline.

## Ranked

The P25 recommendation inspector now includes:

`Save to portfolio`

This stores the selected ranked recommendation without applying it.

## Frontier

The P26 frontier inspector now also includes:

`Save to portfolio`

This lets the user retain several Pareto points instead of repeatedly replacing the active custom bicycle.

# Restore flow

## Restore as active build

Writes the saved selections into the same canonical buildSelections state used by:

- Build Lab
- 3D scene
- Geometry Lab
- Physics Lab
- buildParts URL state

## Restore + inspect in Build Lab

Restores the same saved configuration and opens Build Lab for component/system inspection.

Portfolio does not own a duplicate active-bike state.

# Rename and remove

Saved build names can be edited directly in the selected-build inspector.

Names are capped at 48 characters.

Entries can be removed without affecting the active bicycle.

# URL behavior

P27 extends optimizer UI state with:

- optView=portfolio
- portSc=<comma-separated scenario ids>

P25/P26 state remains supported.

When leaving Portfolio, portSc is removed.

BikeViewer includes portSc in its optimizer cleanup list so leaving Optimize or entering incompatible modes cannot leak stale portfolio UI state.

# Model boundary

P27 is an educational decision workspace.

It does not provide:

- real-world trip-time prediction;
- rider-specific physiological modeling;
- purchasing advice;
- component price/value comparison;
- live inventory;
- reliability prediction;
- structural certification;
- cross-device persistence;
- account sync;
- collaborative portfolios.

Scenario scores are relative decision references over the current Bike Atlas models.
