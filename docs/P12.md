# P12 — Bike Comparison, Geometry & Cross-Archetype Engineering Views

## Objective

Use Bike Atlas's first two complete bicycle families to make engineering differences directly inspectable instead of describing them only in prose.

P12 adds bike-owned reference geometry, derived comparison metrics, component-architecture comparison, a dedicated comparison workspace, and a synchronized translucent 3D ghost overlay.

## Comparison workspace

Explore now exposes **Compare** beside Learn, Workshop and Encyclopedia.

The panel provides:

- primary bike;
- comparison-bike selector;
- swap direction;
- optional 3D ghost overlay;
- headline engineering metrics;
- full geometry table;
- signed deltas;
- shared component-concept count;
- components unique to each architecture.

## 3D ghost overlay

When enabled, the comparison bike is rendered inside the same camera, lighting and world coordinate system as the primary bicycle.

The comparison model:

- uses a cyan translucent material;
- does not write depth like an opaque bike;
- cannot receive clicks/hover/isolation;
- never changes the active semantic selection;
- shares the same orbit camera.

This makes the visual comparison spatial without compromising normal Explore interaction.

The current procedural meshes are calibration assets, so the ghost is a proportional visual aid. Numeric geometry in the panel is the authoritative P12 reference dataset.

- wheelbase: +243 mm

- seat angle: +3.5°
- chainstay: +30 mm
- BB drop: −37 mm
- tire width: +31 mm
- handlebar width: +360 mm
- front travel: +150 mm

Bike Atlas displays these as geometric differences, not universal claims about every road bike or every mountain bike.

## Component architecture

Comparison also derives shared and unique component concepts by semantic slug.

Examples of MTB-specific concepts include:

- rear shock;
- suspension linkage;
- dropper post;
- dropper remote;
- separate flat-bar controls.

Road R1 retains concepts such as its conventional seatpost and two-chainring/front-shifting architecture.

The comparison is generated from the actual semantic bike definitions, so future archetypes automatically participate.

## Deep links

Road primary vs MTB:

```text
/?compare=mtb-m1&overlay=1
```

MTB primary vs Road:

```text
/?bike=mtb-m1&compare=road-r1&overlay=1
```

Ghost disabled:

```text
/?compare=mtb-m1&overlay=0
```

Compare state is removed when entering Story, Learn or Workshop.

## Validation

`npm run validate:domain` now also validates P12 geometry.

Checks include:

- geometry belongs to the intended bike;
- reference-source marker is present;
- all 11 engineering metrics are numeric;
- broad physical sanity ranges;
- Road R1 remains rigid;
- MTB M1 retains front and rear travel;
- MTB tire remains wider than Road R1;
- MTB head angle remains slacker than Road R1;
- the two reference geometries remain meaningfully distinct.
